## Proposed new recipe: prospectively controlled, separately verified

1. **New candidate IDs:** stage two independently copied *clean* source trees under a distinct ignored `artifacts/runtime/p2xa-nos3-v2e-build-<new-id>/primary/source` and `/repeat/source`. Source is canonical pinned `external/nos3` **tracked content plus recursive submodule worktrees**, excluding only the four existing generated directories `cfg/build`, `fsw/build`, `sims/build`, `gsw/build` in the newly staged copies. Perform nonmutating source revision, source/status, submodule/gitdir, copy exclusion, expected nonzero disk, and historical original-lock checks first. Do not overwrite any existing evidence or output. Source paths on the host differ; both OCI binds use the identical container target `/work/nos3`.
2. **Explicit reproducibility-only cFE build metadata (BUILDDATE/HOSTNAME/USER):** in *both* offline Docker builds, set a pinned synthetic label (proposed `BUILDDATE=202610030000`, `HOSTNAME=p2x-v2e-builder`, `USER=p2x-builder`); set Docker `--hostname p2x-v2e-builder` and those variables explicitly. This is a **reproducibility control**, *not the true compilation timestamp or host identity*. Record real UTC host build start and completion separately in provenance. Pin same UID/GID, HOME, OCI digest and `linux/amd64`.
3. **Per-translation-unit compiler launcher:** initialize CMake's `CMAKE_C_COMPILER_LAUNCHER` before each new source tree's *first* CMake configuration. The locked pinned Python executable invokes the original `/usr/bin/gcc` with `-frandom-seed=<stable string>` for each real `.c` source, derived from the normalized `/work/nos3`-relative source path **and normalized container-relative object-output path** (not the host-specific candidate evidence path or timestamp). Distinct source/output identities must produce distinct strings; stable identities across two copies must produce identical strings. Fail closed for ambiguous instrumented `-c`/`-o` invocations, malformed paths, unexpected source outside the pinned container root, duplicate output-key/seed mapping, or missing known `noslink` coverage units. Permit only explicitly documented non-target CMake compiler-identification pass-through. Capture source/target seed mappings and per-build compiler log witnesses.
4. **Unchanged build order and isolation:** run original source `bash ./scripts/cfg/config.sh`, `make build-fsw`, `make build-sim`, `make build-cryptolib` inside each new source copy using the same pinned offline image. Each build gets a new disposable container and separate compile log, with no concurrent shared build tree, host ports, runtime or network.
5. **Prospective strict primary gate:** recompute raw SHA-256 for all *nine* original v2 required output paths, with byte size, across the two new copies. **Require 9/9 raw exact byte identities**; no masks/exclusions of GNU Build ID, embedded cFE configuration, gcov stamps, ELF sections or generated configurations. Compare fixed `BUILDDATE/BUILDHOST/BUILDUSER` and five ELF gcov records with their local `.gcno` as diagnostic checks, not substitutes for raw SHA identity. Use an independent v2e verifier reading *manifest-pinned new primary and repeat* source roots, not the old v2 verifier which deliberately binds primary to `external/nos3` and only understands `p2xa-nos3-v2-build-*`.
6. **Audit and stopping:** capture all four original July lock hashes before and after; assert research root, pristine canonical source, canonical FortyTwo pin and preserved v2 original HOLD. A failed candidate gets an immutable HOLD sidecar; no automatic source-tree cleanup/retry. Successful repeat byte identity yields `V2E_DUAL_OFFLINE_BUILD_BYTE_IDENTITY_PASS__RUNTIME_UNTESTED`, still **not** final Environment v2 acceptance.
