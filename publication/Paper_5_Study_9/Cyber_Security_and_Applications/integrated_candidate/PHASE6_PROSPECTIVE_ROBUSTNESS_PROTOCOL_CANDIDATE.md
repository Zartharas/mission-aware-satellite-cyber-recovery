## 1. Research problem and contribution boundary

The existing datasets were designed primarily for detection, so zero qualified coverage under a restrictive recovery interface is foreseeable. Study 9's action-set and guaranteed-sidecar results follow from an all-unknown vector and an unrestricted Boolean completion space. Study 10's G3 already tested 18 synthetic cases, 22 tests and 1,024 full-Boolean selector/oracle comparisons; repeating that parity test is not a new contribution. The proposed extension tests *source representation discrimination* and *sensitivity to explicitly justified architectural constraints*, not real spacecraft recovery, classifier performance, cryptographic strength or universally required sidecar size.

**P6-RQ1:** Given a specified synthetic recovery-evidence interface, does source-field adjudication discriminate qualified evidence (including known false) from related proxies, missing authority, absent fields and invalid row values?  
**P6-RQ2:** Do explicit, source-grounded architectural restrictions change action-set ambiguity or minimal sufficient sidecars for the same pinned selectors and observation patterns?  
**P6-RQ3:** Where presence of accepted criteria differs from satisfaction of their required values, does the distinction change normalized selector inputs and potential selector/gate interpretation? This is a semantic consistency question, not a recovery success-rate estimate.

Design hypotheses (not results): H1 genuine direct and derivable representations can qualify and invalid substitutes must not; H2 narrowing a nonempty completion set cannot enlarge reachable actions or the smallest guaranteed sufficient sidecar with unchanged semantics; strict reduction is **not** required; H3 completeness and satisfaction are distinct and can disagree. An unchanged ambiguity/sidecar result is meaningful. A failure to distinguish controls falsifies the proposed method for the relevant synthetic contract.

## 3. A newly identified semantic discrepancy (static inspection only)

S9 frozen target says minimum_evidence_complete = all ten recovery criteria **present** in current accepted state. Study 2 runtime _observation uses all(criterion in current ...). The later recovery gate separately requires each applicable value == True, rejects contradictory attested evidence, and rejects residual unauthorized state. G3 _closed_ledger additionally compares expected values and its S10_SYN_N_CRITERIA_VALUE test expects minimum_evidence_complete=false for a present but unexpected value. That is stronger than the frozen presence predicate; selector parity over arbitrary eight-Boolean inputs does not establish evidence-to-predicate parity. The G3 freshness probes were expressly isolated, not synchronized full-state snapshots.

Define M_present and Q_satisfied separately; **only M_present occupies the frozen selector input**. Q_satisfied is reported as a separate diagnostic, never substituted into the primary selector. The old G3 helper can be inspected as a distinct historical test-only comparator if authorized; its outputs must not be relabeled as the normative oracle. In a complete accepted-current ledger with all ten keys but a false value, M_present=true and Q_satisfied=false by definition. This is a design expectation, not an executed test. Incomplete ledger knowledge must be unknown, not false. Actual gate authorization is a separate endpoint, not implied by selector action PROCEED_TO_RECOVERY_GATE.

Ten required keys: approved_version, integrity_measurement_valid, authorization_valid, measured_state_current, authorized_command_path_restored, ground_spacecraft_state_agreed, required_telemetry_restored, health_checks_passed, no_residual_unauthorized_state, recovery_manifest_complete. G3 code and receipts remain historical and unchanged. No numerical S9/S10 mapping result is invalidated by this static discrepancy alone; all accepted native predicates were unknown in both studies. Revisit RQ-E5 language separately before publication, without rewriting G3 PASS.

## 4. Module A: semantic discrimination

**Units:** synthetic schema/target-predicate judgments and separate decision-instance projections; no pooling with S9/S10 real source units. One synthetic fictional subject, a decision ID and time, evidence source/subject/key/epoch/sequence, issuer/verifier trust context, availability window, and source-authority evidence. All synthetic. No real source data, network, operational commands, real keys or private data. Role separation inspired by RATS: producer emits evidence, verifier appraises, decision actor receives qualified state. No RATS conformance claim.

For each of the eight predicates, six candidate strata (48 targeted cases; final exact serialized fixtures and expected rows to be pinned **before execution**):
- D_TRUE / D_FALSE: documented, authoritative decision-visible field with Boolean true/false; DIRECT and known respective value.
- PROXY: operational related non-equivalent field; AMBIGUOUS, unknown, not admitted. For security_signal use a raw nonthresholded anomaly score (not an offline attack label).
- ABSENT: no related qualifying field; ABSENT, unknown.
- WRONG_CONTEXT: semantically named field that is related but stale, offline or wrong subject; no admission, unknown. Class depends on source contract: predeclare AMBIGUOUS for documented related but non-equivalent contextual field. Separate offline-label-only cases below.
- BAD_ROW: a schema with documented direct capability but a missing/malformed row value; capability DIRECT is kept separate from row admission (REJECT_INVALID or UNKNOWN_MISSING). A release with a domain violation cannot be called population-wide operationally direct without a prespecified population-wide disposition. Preserve every case, do not salvage successful rows. This does not change S9's original UNSW rule.

For each predicate the required direct semantic witness and proxy pair are:
signature_valid — known-key verifier outcome bound to evidence / CRC;
source_trusted — current trusted-set membership / source ID;
fresh — authoritative at-decision validity result / timestamp alone;
epoch_valid — expected-epoch equality result / sequence count;
contradictory — accepted latest current claims for same subject/key/epoch with competing values / generic disagreement;
minimum_evidence_complete — all ten required accepted-current keys present in scoped complete inventory / quality score;
security_signal — native decision-visible guard / raw anomaly score;
authorization_available — available authorized path for specified decision / historical command identifier.

**Novel derivations, extension-only registry candidate (do not amend S9/S10 empty registries):** D_FRESH = issue <= decision <= issue + positive validity duration (integer seconds, same trustworthy clock, context and scope, inclusive bounds); D_EPOCH = claimed == expected epoch for same subject at decision instant (nonnegative integers, authoritative expected epoch). For each propose six instances: valid true, valid false, exact boundary/equality case, missing prerequisite, wrong provenance/scope, invalid domain. D_EPOCH exact equality case must use 0 (valid lower domain) distinct from ordinary equal positive epoch. D_FRESH exact boundary use start and use a separate explicit end-boundary fixture in challenge panel. Both registry entries only apply in documented native operational contexts; no classification upgrade from mere field names. Null is not a Boolean. Avoid Python bool-as-int and NaN/infinity, clock mixing or silently defaulting.

**Challenge panel (12 fixed candidate case families):** offline attack label only (ABSENT); documented schema only with no operational field (ABSENT); conflicting duplicate latest sequences (reject/unknown, no coercion); incomplete accepted-claim inventory (unknown completeness/contradiction); nine keys in closed ledger (known M=false); all ten accepted keys with false required value (M=true/Q=false); same required key contradictory (M=false/C=true under complete scope); unrelated-key contradiction with all ten present (M=true/C=true possible outside restricted model); rejected extra claim alongside complete accepted evidence (M may be true while an all-submitted aggregate validity flag is false); stale decision witness for otherwise valid field (unknown); authorization_valid accepted claim true but present-time contact unavailable (M and Q do not imply live path); end-boundary freshness derivation (known true with exact inclusive bound). Challenge expected outcomes are design-level semantic assertions. Exact input cases/roles/classes/values and error codes must be reviewed before freeze; no cases generated or evaluated now.

Proposed total 48 targeted schema/row cases + 12 derivation cases + 12 challenge cases = 72 candidate instances; these are designed deterministic examples, not independent spacecraft trials. Preserve family labels and report each group separately; no pooled inferential statistics. BAD_ROW subtypes, if expanded, must be fixed before freeze and counts amended prospectively. Require explicit class vs row-status columns, provenance, decision context, admitted value (true/false/null), reason and expected comparison. Record disagreements individually. False-admission and false-rejection denominators count prespecified eligible vs ineligible target cases respectively, not all dataset rows. Require exact class match where uniquely specified, exact value/null match, zero unsafe proxy admission and zero false/unknown conflation. Distinguish a fixture-spec defect from a method error; freeze both before scoring, retain failures.

**Anti-circular design:** separate human-readable interface spec and reference expectations from candidate evaluator. Reference expected mappings independently derived from normative contract by an alternate implementation / manual derivation; test evaluator consumes only native schema/record/provenance, not expected outputs or fixture IDs as decision cues. Use a separately implemented oracle, synthetic fixture generator, sealed challenge file and manifest, independent parser, deterministic order and explicit error classes. Baselines: (1) always unknown (expected to fail positives); (2) name-only mapping (expected to admit misleading fields); exact baseline rule/name list must be fixed before freeze; no claim these are strong real-world competitors. Control for label and fixture-ID leakage by renaming fields with corresponding semantic documentation, permuting order, and ensuring labels cannot affect mapping. Fixed perturbation cases and counts to be specified at next design gate. Synthetic controls establish controlled contract discrimination only, not blind human inter-rater validation, and not statistical generalization.

## 5. Module B: architectural state-space sensitivity

Full-cube reference C0 = {0,1}^8, frozen policy identifiers B0/B1/B2/S1, unchanged selector. Enumerate only after authorized freeze/execution. For each nonempty feasible subset F and partial observation o, completions = {x in F: x agrees with o}; empty set => INCONSISTENT_OBSERVATION, not a singleton/zero recovery result. Action set is image of that completion set. A sidecar S is sufficient iff every *realized* assignment to S within completions leaves one action; unrealized assignments are skipped (not counted as successful). Minimal size is min over all subsets, preserve all tied minima. Compare only same nonempty conditioning slice, same selector, same meanings and observed-variable availability. Nested subset guarantees nonexpansion of action set and minimum sidecar; strict reduction/monotone cardinality across nonnested models is not promised.

Candidate models, **architectural hypotheses rather than empirically validated physical state spaces**:
- F0: unrestricted cube (archived reference, not an independent empirical trial).
- F1: required-key closed ledger only, same subject/epoch/decision, contradiction flag covers only the ten required keys. Since current_values excludes conflicting keys, M_present implies not contradictory. This implication is a theorem of the stipulated restricted ledger scope, not a universal Study 2 invariant. Include a nonempty positive witness: ten accepted nonconflicting keys. Include conflicting required-key witness and counterexample outside scope: a contradiction on unrelated key with ten required keys present.
- F2: F1 plus atomic admission-only export architecture, in which when the required set is complete, the entire snapshot of submitted rows is known nonempty and every submitted row is accepted (no rejected extras retained in that exported snapshot). Then M_present implies signature_valid AND source_trusted AND fresh AND epoch_valid, using the frozen aggregation definitions. This is a hypothetical architecture restriction on data publication, not the existing general runtime or mission constraint. Include explicit positive witness and negative witness from general runtime: ten accepted keys plus one rejected extra row; all-required presence can coexist with an aggregate validity failure. Never use F2 to represent a real spacecraft or infer missing observations.

Other proposed implications (completeness implies authorization availability; completeness implies all required values true; no security signal implies safe; trusted implies signature valid; all accepted evidence means all submitted rows valid) are **rejected** absent added architecture assumptions. No arbitrary correlation or probabilistic prior, no tuning F1/F2 based on resulting sidecar minima. Constraints may be overapproximations: each admitted Boolean tuple need not have a concrete ledger witness. Before execution provide independent concrete witness construction/abstract relation proof or clearly report the domain as a logical upper approximation. Never label every F state physically feasible.

Candidate observations: all-unknown primary for all F0/F1/F2; secondary exhaustive partial observations with each predicate one of unknown/false/true (3^8 possible patterns, planned enumeration only). Classify each pattern into feasible/nonfeasible separately by model, compare common feasible patterns, retain full results. No arbitrary weighting or independent-trial claim. Record model size, completion counts, actions, minimum cardinality, all tied sets, changes relative to F0, impossible patterns, and per-policy counterexamples. No policy pooling or superiority claim. All four policies required. For reference F0 all-unknown expected archived action cardinalities 2/2/3/3 and sidecars 6/7/7/8 are **already known**, not held-out hypotheses. Independent verifier via partition by revealed variables vs exhaustive subset oracle, plus mutation tests for wrong unknown handling, missing empty-slice guard, accidental selector modification and false constraint. No new enumeration or numerical result at this design stage.
